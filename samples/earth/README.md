# Earth samples

This directory contains **documentation only**. No raster, crop, or DEM tile is committed
here.

The canonical Earth artifact is the small numeric manifest at
`pipelines/earth/manifests/copernicus_glo90_earth.json`: five observed windows, their
four `terrain-metrics-1.0.0` values, measured WGS84 bounds, analysis CRS, valid fractions,
per-window SHA-256 checksums, and full dataset provenance. It is committed because the API
seed consumes it and because it is small enough to review line by line.

## What is deliberately not committed

- **Raw Copernicus DEM GLO-90 tiles.** Each public COG is roughly 0.36–5.4 MB of compressed
  float32 raster and the dataset is global. Committing tiles would bloat the repository,
  make clones slow, and create an unnecessary redistribution of bulk source data. The
  repository policy forbids large raster binaries and global downloads.
- **The small local crops.** The importer caches padded ~3 km windows as 5–15 KB GeoTIFFs
  under `data/cache/copernicus/`; that directory is gitignored. They are a disposable
  processing cache, not a handoff artifact, and they can be regenerated byte-for-byte from
  the documented S3 keys.
- **Synthetic fixtures.** The offline tests build a temporary synthetic GeoTIFF in
  `tmp_path` to exercise the crop/extraction path. It is clearly marked test-only and never
  enters a manifest or this directory.

If a future fixture is genuinely useful to commit, it must be tiny (well under 1 MB), be
clearly labelled `test-only` or `synthetic`, never be presented as an observation, and be
compatible with the Copernicus terms. The expected committed artifact remains the numeric
manifest, not imagery.

## Reproduce the real values

```bash
uv run python pipelines/earth/ingest_copernicus.py --dry-run
uv run python pipelines/earth/ingest_copernicus.py
```

See `pipelines/earth/README.md` for source URLs, the verified bucket key pattern, licensing,
CRS/resolution details, measured values, byte counts, validation commands, and limitations.
